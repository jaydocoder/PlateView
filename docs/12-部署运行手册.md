# 部署运行手册

## 1. 适用范围

本文用于部署 PlateView 的 Ktor API、PostgreSQL 数据库和 Android 客户端。本系统处理车辆核验资料，真实 Excel、环境变量、数据库备份和签名密钥均不得提交 Git。

## 2. 部署前准备

- 已安装 Docker Engine 与 Docker Compose。
- 已准备一个仅由部署人员保存的 `.env` 文件。
- 已准备 PostgreSQL 备份存储位置。
- 已准备正式 Android 发布密钥与未提交的签名配置。
- 已确定 Android 客户端访问的 HTTPS API 地址。

## 3. 环境变量

以 `.env.example` 为模板，在部署机创建 `.env`，至少设置：

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `JWT_SECRET`，长度不少于 32 个字符
- `INITIAL_ADMIN_PASSWORD`
- `API_PORT`
- `POSTGRES_PORT`

禁止把真实密码、令牌密钥或正式地址写入文档、日志、APK 或 Git。

## 4. 服务启动

```bash
cd /home/neo/project/AiProject/codex-ui/PlateView
docker compose up -d --build
curl --fail http://127.0.0.1:8080/health
```

API 启动时自动执行 Flyway 数据库迁移。首次启动后用初始管理员账号登录，并确认服务日志未出现数据库连接或迁移失败。

审计运维面板、导入差异核对与第六类车辆版本发布顺序固定为先部署 API 并确认 `V13__add_audit_operations_indexes.sql`、`V14__add_import_diff_review.sql`、`V15__allow_incomplete_resident_import_profiles.sql`、`V16__add_other_long_term_vehicle_category.sql`、`V18__add_profiles_and_vehicle_query_statistics.sql`、`V19__add_idempotent_query_event_sync.sql` 已执行，再发布 Android APK。这样可避免新版客户端读取旧接口或数据库约束失败。

### 4.1 七牛云生产部署

生产环境使用 `compose.production.yaml`，由 Caddy 对外提供 HTTPS。PostgreSQL 保持在 Docker 内部网络；API 不映射主机端口，由部署脚本在 `plateview_backend` 和 `plateview_edge` 网络中按 blue/green 槽位启动。Caddy 只通过运行时上游文件访问当前活动 API。

七牛云安全组只需放行 TCP `80`、`443` 和受限来源的 `22`；不得放行 PostgreSQL 或 API 端口。Cloudflare DNS 继续使用 `api.chenxiruyu.dpdns.org`，Caddy 负责 HTTPS 证书和反向代理。

首次启用自动部署时，在服务器初始化 Git 工作区和运行目录：

```bash
ssh qiniuyun
git clone --depth 50 https://github.com/jaydocoder/PlateView.git /opt/plateview/source
mkdir -p /opt/plateview/{runtime,backups,logs/deploy}
chmod 750 /opt/plateview/{runtime,backups,logs/deploy}
```

在服务器 `/opt/plateview/.env` 保留真实环境变量，不再需要手工维护 `PLATEVIEW_IMAGE_TAG`。部署脚本会使用完整 Git 提交哈希作为镜像标签。`.env` 只允许部署用户读取，绝不能提交 Git。

```bash
cd /opt/plateview/source
./deploy/plateview-deploy.sh main
curl --fail https://api.chenxiruyu.dpdns.org/health
```

GitHub 仓库配置以下 Secrets 后，服务端相关提交会自动部署：

| Secret | 用途 |
| --- | --- |
| `DEPLOY_SSH_KEY` | 部署用户专用 SSH 私钥 |
| `DEPLOY_KNOWN_HOSTS` | 服务器 SSH 主机指纹 |
| `DEPLOY_HOST` | 七牛云服务器地址 |
| `DEPLOY_USER` | 部署用户 |
| `DEPLOY_PORT` | SSH 端口 |

工作流文件为 `.github/workflows/server-deploy.yml`。工作流会先检出目标提交，再执行该提交中的部署脚本；候选 API 启动后，脚本必须确认 `flyway_schema_history` 无失败记录，并且数据库最高版本等于源码最高迁移版本，才允许 Caddy 切流。Android、文档和其他非服务端提交不会触发服务器部署。脚本失败时旧 API 容器和 Caddy 上游保持不变。

APK 镜像不再由 GitHub Runner 通过 SSH 上传。部署脚本会安装并启用 `plateview-update-mirror.timer`，服务器每五分钟主动读取 GitHub 最新正式 Release，并用 `curl --continue-at -` 断点续传 `app-release.apk`。文件下载完成后计算 SHA-256，再原子替换 `/opt/plateview/updates/PlateView-v版本号.apk` 和 `latest.json`；下载失败不会影响 API 蓝绿部署，下一次定时任务会继续未完成文件。

查看镜像同步状态和日志：

```bash
systemctl status plateview-update-mirror.timer
systemctl status plateview-update-mirror.service
journalctl -u plateview-update-mirror.service -n 100 --no-pager
```

查看部署日志：

```bash
ls -lt /opt/plateview/logs/deploy
tail -f /opt/plateview/logs/deploy/deploy-*.log
```

手工回滚到上一版本：

```bash
/opt/plateview/source/deploy/plateview-deploy.sh rollback
curl --fail https://api.chenxiruyu.dpdns.org/health
```

首次启动会自动执行 Flyway 迁移并创建初始管理员。生产数据导入只能在 HTTPS 服务可用后，通过管理员工作台上传；真实 Excel 不上传到 Git 或服务器源代码目录。

## 5. 备份与恢复

部署前和每次导入发布前执行逻辑备份：

```bash
docker compose exec -T postgres \
  pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc \
  > plateview-日期.dump
```

恢复必须在独立数据库先演练。确认无误后，按备份恢复手册处理数据库。业务导入错误优先使用管理员工作台的批次回滚，不以数据库恢复替代可追溯的业务回滚。自动部署不会执行 Flyway 降级迁移。

## 6. Android 配置与构建

### 6.1 首次创建本机发布签名

正式签名密钥只创建一次，位于当前用户目录的 `~/.android/plateview-release.jks`。执行以下脚本后，在弹出的终端中由发布负责人输入并保存密钥密码：

```bash
cd android
./scripts/create-release-signing.sh
```

脚本会写入未提交的 `android/keystore.properties`，Gradle 只从该本机文件读取密钥位置、别名和密码。严禁提交该文件、`.jks` 文件或在聊天、文档、日志中记录密码。必须离线备份密钥和密码；丢失后无法使用同一应用标识覆盖安装后续正式版本。

### 6.2 构建正式 APK

构建前通过 Gradle 属性设置正式 HTTPS 地址：

```bash
cd android
./gradlew :app:assembleRelease \
  -PplateviewApiBaseUrl="https://示例域名/"
```

正式构建必须配置发布签名后再执行。未签名 `app-release-unsigned.apk` 只能用于构建验证，不得分发或安装为正式版本。

签名完成后，正式 APK 输出为：

```text
android/app/build/outputs/apk/release/app-release.apk
```

验证签名并安装到 USB 连接的真机：

```bash
apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
adb uninstall com.jaydocoder.plateview
adb install app/build/outputs/apk/release/app-release.apk
```

正式签名与调试签名不同。若设备已安装调试包，首次安装正式包前必须卸载调试包；此后使用同一正式密钥构建的版本可正常覆盖更新。

## 7. 发布后检查

1. `GET /health` 返回 `ok`。
2. 管理员登录成功。
3. 普通用户完成首个有效车牌字符触发的模糊查询与详情核验。
4. 普通用户请求任一 `/admin/*` 接口返回 403。
5. 管理员可看到导入、车辆、账号和审计记录；导入核对页默认隐藏完全一致记录，并可查看字段原值、新值、待失效和恢复有效详情。
6. 用户名为 `admin` 的管理员可手工新增六类车辆；其他管理员新增表单只显示“其他长期通行车辆”，并且无法改变已有车辆类别。
7. “其他长期通行车辆”必须填写单位名称；首页在线与离线候选均显示“单位名称：…”。
8. 设备安装正式签名 APK，验证版本号、登录、手动输入、详情、历史与管理员工作台。
9. `https://api.chenxiruyu.dpdns.org/updates/latest.json` 返回当前版本、APK 地址与 SHA-256；通过 HTTP Range 请求 APK 时服务器返回 `206`，确认服务器镜像可用于断点续传。
10. `systemctl status plateview-update-mirror.timer` 显示已启用；手动运行 `systemctl start plateview-update-mirror.service` 后，若 GitHub Release 未变化，日志显示“镜像已是最新版本”。

## 8. 故障处理

- 数据库迁移失败：停止 API，保存日志，核对数据库连接和迁移版本，不得手工修改 Flyway 历史表。
- Excel 发布失败：查看批次异常行和状态，修正源数据后新建批次；已发布批次使用工作台回滚。
- Android 无法连接：核对正式 API 地址、HTTPS 证书、网络可达性和 Android 网络安全配置。
- 登录失败：核对账号启用状态。账号状态仅为 `ACTIVE` 或 `DISABLED`，车辆状态仅为 `ACTIVE` 或 `INACTIVE`。
- 自动部署失败：先查看 GitHub Actions 日志和 `/opt/plateview/logs/deploy`，确认 Caddy 仍指向旧槽位；不要删除旧容器和旧镜像。
- 候选容器失败：脚本会停止候选容器并返回失败，公网流量不切换；修复提交后人工重新运行工作流。
- 切换后接口异常：执行 `plateview-deploy.sh rollback`，确认上一容器存在后恢复 Caddy 上游。

## 9. 自动部署验收

- 服务端提交触发工作流，纯 Android 提交不触发。
- 构建失败、迁移失败或候选健康检查失败时，旧版本 `/health` 仍返回成功。
- 成功部署后 `active-slot`、`active-upstream` 和 `active-commit` 与线上版本一致。
- 连续两次部署和一次手工回滚均通过后，才允许清理旧镜像和容器。
