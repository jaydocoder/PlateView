# 性能测试报告

## 1. 服务端查询性能

- 环境：独立 Docker Compose 的 Ktor API 与 PostgreSQL。
- 前置数据：村民工作簿发布后的隔离数据。
- 方法：管理员登录后，对大小写归一化的四字符车牌关键字连续执行 30 次已认证查询。
- 指标：P95 响应时间。
- 结果：`0.005884 秒`。
- 结论：低于“已认证查询 P95 小于 1 秒”的验收目标。

## 3. Android 12 真机性能与恢复

- 设备：RMX3461，Android 12，API 31。
- 调试连接：APK 使用 ADB 反向端口映射访问隔离 API；隔离数据只包含虚构验收车辆。
- 冷启动：强制停止后启动三次，耗时为 945、965、942 毫秒，中位数为 945 毫秒。
- 内存：运行期总 PSS 为 141429 KB，总 RSS 为 242184 KB。
- 断网恢复：停止 API 后，查询页显示“无法连接车辆数据服务”和“重新查询”；API 恢复并稳定后，选择重试可重新得到候选。
- 语音：真机已授予录音权限并运行语音入口；JVM 测试覆盖识别结果回填、归一化和查询触发。未采集或保存现场口述音频。

本轮未采集 Perfetto Trace，因此未创建 Trace 分析证据链。后续出现启动、内存或卡顿问题时，再按专项流程采集 Trace 并分析。
