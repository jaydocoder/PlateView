# 数据库设计

## 1. 范围与结构来源

本文描述 PlateView 在 PostgreSQL `plateview` 数据库、`public` Schema 中的完整表结构。字段、默认值、主键、外键、检查约束和索引以 Flyway 迁移脚本及 2026-08-16 对七牛云生产数据库执行的只读元数据核验为准。

- 业务与运行表：10 张。
- Flyway 内部迁移表：1 张。
- 表结构的唯一变更入口：`server/src/main/resources/db/migration/`。
- 下文“说明”是项目数据字典说明；当前 SQL 结构未为各字段定义 PostgreSQL `COMMENT`。

### 1.1 阅读说明

| 列 | 含义 |
| --- | --- |
| 可空 | `否` 表示 `NOT NULL`；`是` 表示允许 `NULL`。 |
| 默认值 | 未填写表示数据库不提供默认值，写入方需显式提供值或使用 `NULL`。 |
| 键与约束 | `PK` 为主键，`FK` 为外键，`UQ` 为唯一约束，`CK` 为检查约束。 |
| `ON DELETE` | 未特别标注时使用 PostgreSQL 默认限制行为；`CASCADE` 为级联删除；`SET NULL` 为将外键置空。 |

### 1.2 表关系概览

```text
users ──< refresh_sessions
  ├──< audit_logs
  ├──< import_batches ──< import_rows ──< import_effects
  └──< 车辆、分类档案与导入记录的创建/更新人字段

import_batches ──< vehicles
vehicles ── 0..1 resident_profiles
vehicles ── 0..1 long_term_profiles

vehicle_catalog_state 为单行目录版本状态表
flyway_schema_history 为 Flyway 内部迁移历史表
```

## 2. 表清单

| 表 | 类型 | 职责 |
| --- | --- | --- |
| `users` | 业务表 | 账号、角色、状态、密码哈希与操作人追踪。 |
| `refresh_sessions` | 运行表 | 登录刷新令牌会话及撤销状态。 |
| `vehicles` | 业务表 | 车辆主档案与车牌检索键。 |
| `resident_profiles` | 业务表 | 村民车辆的姓名、身份证号、联系方式与备注。 |
| `long_term_profiles` | 业务表 | 长期车辆的单位、通行人员、通行说明与备注。 |
| `import_batches` | 业务表 | 一次 Excel 上传、预览、发布和回滚的批次主记录。 |
| `import_rows` | 业务表 | Excel 源行及其解析、正式库对照、处置、异常和发布关联。 |
| `import_effects` | 业务表 | 已发布导入行的创建、更新、失效、恢复效果与回滚快照。 |
| `audit_logs` | 运行表 | 查询和管理操作的只追加审计记录。 |
| `vehicle_catalog_state` | 运行表 | Android 完整车辆目录快照的版本号。 |
| `flyway_schema_history` | Flyway 内部表 | 已执行迁移的版本、脚本、校验和和执行结果。 |

## 3. 字段级数据字典

### 3.1 `users`：账号表

| 字段 | 类型 | 可空 | 默认值 | 键与约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 身份列 | PK | 用户唯一标识。 |
| `username` | `VARCHAR(64)` | 否 | 无 | UQ `uq_users_username` | 登录账号，数据库内唯一。 |
| `password_hash` | `VARCHAR(255)` | 否 | 无 | 无 | 密码哈希值，不保存明文密码。 |
| `role` | `VARCHAR(16)` | 否 | 无 | CK：`ADMIN`、`USER` | 用户角色。 |
| `status` | `VARCHAR(16)` | 否 | `ACTIVE` | CK：`ACTIVE`、`DISABLED` | 账号启用状态。 |
| `version` | `INTEGER` | 否 | `0` | 无 | 乐观锁版本号。 |
| `created_at` | `TIMESTAMPTZ` | 否 | `CURRENT_TIMESTAMP` | 无 | 创建时间。 |
| `updated_at` | `TIMESTAMPTZ` | 否 | `CURRENT_TIMESTAMP` | 更新时间触发器 | 最后更新时间。 |
| `created_by` | `BIGINT` | 是 | 无 | FK → `users.id` | 创建该账号的操作人；初始管理员可为空。 |
| `updated_by` | `BIGINT` | 是 | 无 | FK → `users.id` | 最后修改该账号的操作人。 |

| 索引名 | 类型 | 字段/条件 | 说明 |
| --- | --- | --- | --- |
| `users_pkey` | B-tree 唯一 | `id` | 主键索引。 |

## 4. 通用约束、触发器与设计规则

1. `users`、`vehicles`、`resident_profiles`、`long_term_profiles`、`import_batches` 和 `import_rows` 的 `updated_at` 由 `update_updated_at_column()` 触发器在更新时自动维护。
2. `vehicles` 使用 `version` 支持管理员编辑的乐观锁；分类资料与导入批次同样保留版本字段，支撑导入发布与回滚冲突检查。
3. 一辆车按类别关联一条村民档案或一条长期车辆档案，不应同时维护两条分类档案。
4. `vehicles.status = 'INACTIVE'` 表示逻辑停用；有效车辆的归一化车牌才受唯一索引约束。
5. Excel 导入遵循“差异预览、人工处置、事务发布、效果快照回滚”流程；预览阶段不会直接写入正式车辆表。对已识别类别，Excel 缺失的有效车牌仅在管理员确认后逻辑失效。
6. `audit_logs` 是只追加审计表；应用不提供业务更新或删除接口。
7. `vehicle_catalog_state.revision` 变化后，Android 客户端应在下次版本校验时替换本地完整目录快照。

## 6. 维护要求

- 新增、修改或删除字段、约束、索引时，必须先新增 Flyway 迁移，再同步更新本文。
- 不得通过 Navicat 直接调整表结构、删除 Flyway 历史或修改迁移校验和。
- 执行结构迁移前必须先备份数据库；业务数据导入错误优先使用导入批次回滚，而不是手工修改关联表。
