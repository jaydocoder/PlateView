# ADR-006：Android 加密车辆缓存与目录版本同步

- **状态：** 已接受
- **日期：** 2026-08-08

## 背景

车辆目录更新频率较低，但候选目录全量缓存、详情按需缓存时，首次打开详情仍需等待远程接口，无法满足弱网下快速核验。

## 决策

- 服务端以目录版本作为缓存一致性边界；Android 通过目录版本接口确认是否需要同步。
- Android 使用独立 SQLCipher Room 数据库保存设备共享的完整有效车辆快照。随机数据库密码仅以 Android Keystore AES-GCM 密钥加密后保存。
- 服务端完整目录接口必须携带预期版本；版本不一致时返回冲突，客户端丢弃临时代次并重新同步。
- 分页下载写入不可见的临时代次，全部完成后在单个 Room 事务中切换活动代次；失败时保留旧快照。
- 首页候选和详情页均读取活动快照；首次尚无快照时保留既有远程查询作为临时兜底。
- 应用启动、查询页恢复前台和登录后的查询页初始化都会触发版本检查；WorkManager 在联网条件下以最短允许的约 15 分钟周期同步。
- 退出登录仅删除会话和搜索历史，设备共享快照保留供下一位已登录用户复用。

## 后果

- 弱网下重复查询与已查看详情可快速返回，本机不缓存令牌。
- 目录版本查询本身仍需要网络；离线时仅使用未过期详情和已有候选快照。
- Keystore 密钥失效会使缓存无法解密，此时必须清除缓存数据库并重新同步，不影响服务器原始数据。
- 管理员写入、导入发布和回滚由服务端目录版本触发客户端失效，无需 Firebase 推送。
