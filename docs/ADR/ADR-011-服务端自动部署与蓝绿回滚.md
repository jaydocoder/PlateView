# ADR-011：服务端自动部署与蓝绿回滚

## 状态

已接受。

## 决策

服务端提交由 GitHub Actions 在托管运行器上完成测试与 Buildx 镜像构建，推送到 GHCR 后通过 SSH 调用七牛云服务器部署脚本。服务器只按不可变摘要拉取镜像、在需要执行迁移时备份 PostgreSQL，并启动受资源限制的非活动槽位。候选容器和公网健康检查均通过后，Caddy 通过 graceful reload 切换上游；失败时保留旧容器和旧上游。

Compose 只管理 PostgreSQL 与 Caddy，API 由部署脚本管理 blue/green 容器。运行时 Caddy 配置放在未提交的 `runtime/Caddyfile`，当前槽位和回滚容器记录在 `runtime` 状态文件中。

`runtime` 目录以 bind mount 提供给 Caddy，切流和回滚通过替换目录内的 `Caddyfile` 更新上游。不得把运行时配置作为单文件 bind mount，避免容器持有旧文件视图而无法读取新上游。

每次成功切流后，只保留新活动容器和刚退出流量的上一版本容器；上一容器停止运行但可由回滚流程重新启动。更早的 `plateview-api-*` 容器，以及不被这两个容器引用的本地或 GHCR API 镜像，都会尽力回收。清理失败不影响已经通过公网健康检查的部署结果。

## 约束

- 只有服务端路径变化触发部署，Android 发布流程独立运行。
- 每日低优先级 PostgreSQL 压缩备份默认保留 14 天；仅迁移版本变化的部署额外生成发布前备份。
- 服务器必须具备至少 1GiB 交换空间并设置 `vm.swappiness=10`；部署前资源检查不通过时拒绝启动候选容器。
- Flyway 只向前执行，不自动降级；迁移必须兼容仍在运行的旧 API。
- 使用 `flock` 拒绝并发部署，失败后人工重试。
- 日志不得包含密码、令牌或完整环境变量。

## 结果

服务器构建失败、迁移失败、候选健康检查失败或切流后的公网检查失败，均不会把流量切到新版本。切流后如发现业务异常，使用部署脚本的 `rollback` 命令切回上一容器；数据库迁移回退另行按备份恢复流程处理。
