# ADR-010：内部维护长期车辆类别与建档权限

## 背景

现有五类车辆由 Excel 核对表驱动。内部仍需要维护不属于五类的长期通行车辆，且不能让普通管理员手工新增五类正式数据或通过改类绕过导入流程。

## 决策

1. 新增 `OTHER_LONG_TERM`，显示为“其他长期通行车辆”，复用 `long_term_profiles`。
2. 第六类仅允许手工维护，不参与 Excel 自动识别、差异比较、全量失效和发布回滚。
3. 用户名严格为 `admin` 且角色为管理员的账号可新增和改动全部六类。
4. 其他管理员仅可新增第六类；可编辑已有车辆资料与状态，但不能变更类别。
5. 第六类必须填写单位名称，首页候选同时显示车辆类别和单位名称。
6. `KANAS_TOURISM_DEVELOPMENT` 的显示名称统一简化为“喀旅公司车辆”，不变更枚举值和历史数据。

## 后果

- 五类正式数据继续以 Excel 导入为主，内部补充档案有独立且明确的类别。
- 类别权限必须由服务端根据当前账号裁决，Android 仅负责按服务端能力隐藏不可用选项。
- 本地完整快照增加单位名称字段并升级 Room 数据库迁移，以保证离线候选展示一致。
