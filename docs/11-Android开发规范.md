# Android 开发规范

## 1. 技术基线

- 语言：Kotlin。
- 最低 SDK：31；支持 Android 12 及以上。
- UI：Jetpack Compose 与 Material 3，不新增 XML Layout。
- 架构：MVVM、Clean Architecture、Hilt、Navigation Compose、Coroutines、Flow。
- 本地存储：Room 仅保存搜索历史。

## 2. 模块与目录

代码按特性组织，而非按技术类型集中堆放。首版至少包含：

```text
android/app/
  core/                 通用网络、设计系统、导航和错误模型
  feature/auth/         登录
  feature/search/       手动与语音搜索、候选、历史
  feature/vehicle/      车辆详情
  feature/admin/        用户、车辆、导入与审计管理
  data/                 API、Room、仓库实现
  domain/               用例、仓库接口和领域模型
```

当模块数量增加且编译边界明确后，再拆分 Gradle 多模块；首版不为拆分而拆分。

## 3. 界面与状态

- 每个屏幕定义不可变 `UiState`、用户事件和一次性效果。
- ViewModel 使用 `StateFlow` 持有状态；Compose 使用具备生命周期感知的方式订阅。
- Composable 只负责渲染和派发事件，不直接调用网络、Room、语音服务或业务用例。
- 列表项提供稳定键；非平凡 Composable 独立文件。
- 所有加载、空结果、网络失败、权限拒绝和并发冲突均是明确状态，不使用静默失败。

## 4. 导航

- 目的地参数使用类型安全对象，不拼接字符串路由。
- 登录态决定查询图与管理图的入口；管理员能力由后端角色和界面状态共同控制。
- 车辆详情只接收车辆标识，不把完整身份信息通过导航参数传递。
- 返回操作必须恢复搜索输入、候选与滚动位置。

## 5. 数据与错误处理

- API DTO 与领域模型分离，由仓库完成映射。
- 所有挂起调用由用例或仓库封装；ViewModel 不暴露网络实现细节。
- 统一映射认证失效、无权限、无结果、网络不可用、服务异常和版本冲突。
- 日志禁止输出密码、令牌、身份证号、联系方式和完整详情。

## 6. 依赖注入与命名

- 使用 Hilt 提供 API 客户端、仓库、用例、Room 和系统服务适配器。
- 类名使用领域含义，例如 `SearchVehiclesUseCase`、`VehicleRepository`、`SearchUiState`。
- 布尔值以状态命名；事件使用动词；避免缩写和通用的 `Manager`、`Helper` 命名。
- 注释使用中文，只说明约束、意图或非直观原因。

## 7. 测试要求

- ViewModel、用例、车牌归一化、候选排序和历史记录必须有单元测试。
- 关键 Compose 页面必须覆盖输入、候选点击、详情跳转、错误状态和状态恢复。
- 语音识别、录音权限和网络失败使用可替换适配器与测试替身。
- 每项功能提交前运行相关单元测试、静态检查和受影响的 Android 测试。

## 8. Git 约定

- 一个提交只完成一个可验证的主题。
- 提交信息使用简体中文，描述结果而非过程。
- 不提交 Excel 原始数据、密钥、环境变量、APK、构建目录或真实个人信息。
- 每次提交在提交说明或进度日志中记录已运行的本地验证。

## 9. 普通用户查询流程落地约定

- `SearchViewModel` 以 `StateFlow<SearchUiState>` 管理输入、候选、历史和查询反馈，以 `Flow<SearchEvent>` 发送一次性详情导航事件；界面不得持有仓库或直接发起请求。
- 搜索顺序固定为“输入原文 -> 车牌归一化 -> 250 毫秒防抖 -> 四字符门槛 -> 仓库查询”。归一化统一大写，因此前端和服务端均不受英文字母大小写影响。
- `SearchRoute` 负责申请 `RECORD_AUDIO` 运行时权限；`VoiceRecognizer` 只适配系统语音服务。任何权限或识别故障都必须回退为手动输入，而不是阻断查询页。
- `SearchDestination` 和 `VehicleDetailDestination` 使用序列化类型安全目的地；详情路由只携带 `vehicleId`，由详情 ViewModel 从仓库重新读取当前数据。
- 搜索历史通过 Room 的 `search_history` 表按 `username` 查询、删除和清空，最多保留 50 条。实体禁止新增身份证号、联系方式、完整详情、令牌或语音原文列。
- 交互控件应提供可理解的文本或 `contentDescription`；候选、历史和详情字段使用稳定键，查询、失败和空结果必须以文本状态可被辅助功能读取。

## 10. 管理工作台落地约定

- 管理路由仅在当前会话角色为 `ADMIN` 时注册；查询页只向管理员显示工作台图标。客户端隐藏入口不替代服务端的 `requireAdministrator()` 鉴权。
- `AdminWorkspaceViewModel` 管理概览、车辆、账号、导入与审计状态。网络、文件读取和导入工作流全部经 `AdminRepository` 与 `AdminImportFileReader` 注入，不进入 Composable。
- 车辆、账号编辑必须在请求头携带服务端返回的当前版本号；HTTP 409 映射为明确的冲突状态，界面提示刷新后重新编辑。
- 删除车辆统一调用逻辑停用接口；管理表单按车辆类别切换村民资料与长期车辆资料，并且只提交预定义的附加字段。
- Excel 使用 `OpenDocument` 系统选择器，不请求宽泛存储权限；选择后立即读取并上传预览，批次详情中的待处理行必须先显式选择发布或跳过。
- 管理列表使用稳定键、可滚动标签和带内容说明的图标按钮。长编辑表单与导入行列表必须设置最大高度，避免小屏设备出现无界测量或内容遮挡。
