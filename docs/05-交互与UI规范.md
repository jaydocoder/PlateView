# 交互与 UI 规范

## 1. 设计方向

用户为景区入口或巡查人员，页面首要任务是快速确认车辆归属。视觉采用冷杉深绿、冰湖浅色、核验青、通行琥珀和异常红；使用系统中文字体，车牌使用接近真实比例的蓝/黄标识组件。

## 2. 页面

| 页面 | 普通用户 | 管理员附加能力 |
| --- | --- | --- |
| 登录 | 账号密码登录 | 相同 |
| 查询 | 手动输入、语音输入、候选列表、历史记录 | 相同 |
| 车辆详情 | 核验详情 | 编辑入口 |
| 管理工作台 | 无 | 用户、车辆、导入、审计入口 |
| 导入中心 | 无 | 上传、预览、异常处理、发布、回滚 |

## 3. 查询交互

- 输入归一化后少于 4 个有效车牌字符时不请求服务，仅提示继续输入。
- 输入变化后 250 毫秒发起查询；新请求取消旧请求。
- 候选项仅显示车牌和车辆所属类型；点击后导航至详情页核验完整资料。
- 语音按钮请求录音权限，识别结果写入同一搜索框，允许编辑后继续搜索。
- 历史记录按时间倒序，支持单条删除与清空；退出账号后不显示另一账号的记录。

## 4. 状态规范

| 状态 | 界面行为 |
| --- | --- |
| 加载中 | 保持输入可编辑，候选区域显示紧凑加载状态。 |
| 无匹配 | 明确显示未找到匹配车牌，不清空输入。 |
| 网络不可用 | 显示无法连接车辆数据服务，不展示旧详情。 |
| 语音失败 | 说明语音未识别，保留已输入内容并提供手动输入。 |
| 无管理员权限 | 不展示管理入口；直接访问时返回权限不足页。 |
| 编辑冲突 | 提示数据已更新，展示刷新与重新编辑操作。 |
