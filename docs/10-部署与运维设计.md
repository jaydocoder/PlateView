# 部署与运维设计

## 1. 交付组成

- Ktor API Docker 镜像。
- PostgreSQL Docker 服务和持久卷。
- Docker Compose 编排文件。
- 数据库版本化迁移脚本。
- 不含真实值的环境变量示例文件。

## 2. 环境变量

部署环境提供数据库连接、令牌签名密钥、初始管理员密码、允许的客户端地址和日志级别。真实变量文件不得提交 Git。

## 3. 健康与日志

- API 提供 `/health` 健康检查。
- 日志记录请求标识、账号标识、状态码和耗时；不得包含密码、令牌、身份证号和联系方式。
- 导入和管理操作通过审计表追溯，不依赖普通应用日志。
- 审计运维面板和导入差异核对依赖 Flyway 索引、对照快照与动作约束；部署 API 时必须先完成迁移，再发布读取新响应的 Android APK。

## 4. 备份与恢复

- PostgreSQL 每日逻辑备份并保留可配置的备份周期。
- 每次导入发布前保留批次记录，支持业务层回滚。
- 发布前执行一次从备份恢复到独立数据库的演练，并记录结果。

## 5. 发布检查

- 执行数据库迁移和健康检查。
- 验证初始管理员可登录。
- 验证 Android App 的 API 地址、登录、搜索和详情查询。
- 验证管理员审计默认近 30 天、异常筛选、分页汇总与索引迁移结果。
- 验证 `V14__add_import_diff_review.sql` 已执行，管理员可查看字段差异、确认失效或恢复，并且存在待确认项时发布接口返回冲突。
- 验证调试 APK 与正式签名 APK 的签名和安装结果。

## 6. 服务端自动部署

- GitHub Actions 仅监听 `server/**`、`compose.production.yaml`、`deploy/**` 和 `infra/**`。
- 工作流通过 SSH 调用服务器 `/opt/plateview/source/deploy/plateview-deploy.sh`，服务器自行拉取提交并使用 Docker BuildKit 构建 API 镜像。
- PostgreSQL 备份先于迁移和候选容器启动，备份默认保留 14 天。
- API 使用 blue/green 槽位运行；候选容器启动后必须确认 Flyway 不存在失败记录且已执行至源码最高迁移版本，再执行候选健康检查和公网 `/health`，最后由 Caddy graceful reload 切换上游。
- 构建、迁移、健康检查或 Caddy reload 失败时，不切换流量并删除候选容器，旧版本继续服务。
- 切换后保留上一版本容器、镜像和上游信息，必要时执行 `plateview-deploy.sh rollback`。
- 使用 `flock` 拒绝并发部署；失败的工作流需人工重新运行，不自动跳过版本。
- 部署日志写入 `/opt/plateview/logs/deploy`，不得写入密码、令牌或完整环境变量。
- Android 正式标签发布会将同一签名 APK、SHA-256 与 `latest.json` 原子同步到 `/opt/plateview/updates`；Caddy 支持 HTTP Range，客户端可从 GitHub 失败位置续传至服务器镜像。
