# Excel 导入与数据质量规范

## 1. 数据源

| 来源 | 工作表或字段特点 | 目标分类 |
| --- | --- | --- |
| 村民车辆统计表 | 姓名、身份证号、车牌号、联系方式、备注 | 村民车辆 |
| 长期通行工作用车统计表：驻景区单位 | 单位跨行继承 | 驻景区单位 |
| 长期通行工作用车统计表：驻景区企业 | 通行人员字段可能包含混合文本 | 驻景区企业 |

## 2. 导入流程

1. 管理员上传 Excel，系统创建导入批次，不修改正式数据。
2. 解析器按工作表映射字段，继承空白单位名称，生成归一化车牌；支持普通车牌、警车后缀和应急车后缀，并完整保留后缀作为检索键。
3. 系统以本次 Excel 中成功识别的车辆类别为覆盖范围，计算新增、字段更新、恢复有效、待失效、完全一致和解析异常六类结果；未出现在本次 Excel 的其他类别不受影响。
4. 默认只展示需要核对的新增、字段更新、恢复有效、待失效和解析异常行。正式库完全一致及同批重复行均隐藏，仅在汇总中计数。
5. 管理员在“查看更新详情”中核对字段级原值与新值。更新、恢复、待失效和带告警新增均需明确选择发布或跳过；异常行不可发布。
6. 全部待确认项完成处置且至少有一项选择发布后，才能发布批次。预览按页返回，继续下滑才加载后续记录。
7. 发布在单个事务中执行，失败则整体回滚；成功后记录审计和版本信息。

## 3. 异常规则

| 情况 | 处理 |
| --- | --- |
| 车牌为空或无法归一化 | 异常，禁止发布该行。 |
| 警车或应急车后缀 | 识别为完整车牌，后缀参与唯一校验和模糊查询，不截断为普通车牌前缀。 |
| 单元格存在多个可识别车牌 | 拆分后进入待确认记录；无法确定关联字段时标记异常。 |
| 规范化车牌与正式库冲突 | 显示来源与字段差异，管理员选择更新、保留或放弃。 |
| 已失效车牌再次出现在 Excel | 同车牌仅有一条失效历史档案时生成“恢复有效”；存在多条失效历史档案时标记异常，不自动恢复。 |
| 本次已识别类别中缺失的有效车牌 | 生成“待失效”系统差异行；管理员确认后将车辆状态改为 `INACTIVE`，选择保留则维持有效。 |
| 与正式库字段完全一致 | 标记为隐藏一致记录，不发布、不改变车辆版本或目录版本。 |
| 身份证号或联系方式格式异常 | 标记警告，管理员确认后可发布。 |
| 单位名称为空 | 仅可继承上一有效单位；首条无单位记录为异常。 |
| 姓名、身份证号、联系方式、车辆类型、单位名称或通行人员超过数据库字段上限 | 异常，定位到源行后修正，不阻断同批次其他合格记录。 |

## 4. 可追溯性与回滚

每条导入记录保存批次号、源文件标识、工作表名、源行号、原始值、解析值、预览时的正式库快照、计划动作和处理状态。系统生成的待失效行以“系统差异检测”标识来源，不伪装成 Excel 源行。管理员可回滚已发布批次，回滚行为同样进入审计记录。

发布时系统为每条实际创建、更新、失效或恢复的车辆写入效果快照。回滚前必须确认车辆版本仍与发布结果一致；存在后续编辑或其他批次更新时，系统拒绝整个回滚操作，避免覆盖后续数据。
