# 回滚演练报告

## 演练环境

- 时间：2026-08-06
- 环境：独立 Docker Compose 项目、独立 PostgreSQL 卷与虚构测试凭据。
- 数据源：项目根目录两份未提交的真实 Excel 工作簿。
- 数据保护：命令输出仅包含状态、计数、类别和耗时，不记录个人信息。

## 演练步骤与结果

| 步骤 | 结果 |
| --- | --- |
| 启动隔离 PostgreSQL 与 API | 通过。Flyway 应用 4 条迁移，9 张业务表存在。 |
| 预览村民车辆工作簿 | 通过。识别为村民车辆，存在可发布行。 |
| 处理待确认行并发布村民批次 | 通过。发布后大小写模糊查询和村民详情可用。 |
| 回滚村民批次 | 通过。批次状态为 `ROLLED_BACK`，抽样车牌不再可查询。 |
| 预览长期工作簿 | 通过。识别驻景区单位、驻景区企业、干部、喀纳斯旅游发展股份有限公司四类。 |
| 发布长期批次并查询详情 | 通过。长期车辆详情含长期资料。 |
| 回滚长期批次 | 通过。批次状态为 `ROLLED_BACK`。 |
| 检查最终数据库 | 通过。活动车辆数为 0，已回滚批次数为 2。 |

## 结论

业务层导入回滚可恢复本次演练产生的数据，并保留批次与审计追溯。生产发布仍须在每次发布前执行数据库备份；若发生批次外的人工编辑或后续批次更新，系统会以版本冲突拒绝不安全回滚。
